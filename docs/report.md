**最终报告（2026-10-24）：默认配置同时达到 Tier 3。** 唯一官方要求为 [README-EN.md](../README-EN.md)。总面积 **30186.042 µm²**、频率 **300.823 MHz**、IPC 几何平均 **1.104759629**。同一份生产 RTL 通过完整正确性、延迟与 ISA 回归及严格结构/指标审计，详情和复现见 [validation.md](validation.md)。

**参数敏感性**

默认：ISSUE_WIDTH=2、DECODE_WIDTH=2、ROB32、PRF64、IQ8、LDQ8、STQ16、I$ 2 KiB、D$ 16 KiB、ASSOC=1、WB_BYPASS=1、EARLY_REDIRECT=0、BTB64。以下实验使用最终生产 RTL 的冻结副本，仅修改所列参数。八个变体均通过官方正确性 19/19 和全部六项性能测试；只对默认配置给出最终面积/频率，不将不同配置的指标组合。

单发射、单路分派/提交及较小 ROB/IQ 会降低吞吐。ROB64 可继续提高 IPC，但需要单独评估面积与频率；本轮选择已完成全部指标验收的 ROB32。PRF128 没有收益，因此保留 PRF64。两路相联保持总容量不变，但替换和冲突时序会改变 IPC，不能只凭相联度推断收益。

**架构探索与取舍**

1. 综合完整性先于分数。三处 package 结构体数组曾被原生 Yosys 错误展开；改为等宽位向量数组后，IFB、IQ 指令和写回 FIFO 得以完整展开。删除 keepdc 包装器并撤回旧 PPA。SRA/SRAI 的 signed/unsigned 混合表达式也已修正。
2. 面积/频率阶段通过缩小缓存和窗口、关闭同拍旁路，达到 28,683.282 µm² / 375.780 MHz，但 IPC 只有 0.896022。用户随后要求同时满足三项 Tier 3，故撤销过度牺牲 IPC 的部分：重新开启旁路，恢复 ROB32/STQ16，扩大 IQ/LDQ 至 8。
3. 原逻辑在这个窗口下的 IPC 达到 1.104763，但 BTB64 版本频率仅 250.122 MHz。提前前端恢复可取得更高 IPC，却形成更长组合路径，因此保留寄存恢复。BTB128 减为 64 不改变该阶段六项计数，节省约 1,995 µm²。
4. IQ 的变量索引串行轮转扫描改为并行资格掩码，内存年龄选择也并行化；保留发射次序、store 顺序、load 不能越过未发射老 store 的规则。单独采用它时频率为 283.186 MHz，尚未达标。
5. LSQ 的串行 guard/load 选择先试平衡树，再改为共享的并行年龄比较：较晚到达的资格不再经过多级年龄 key mux 和比较器。恢复拍统一暂停 load 调度，较老 load 下一拍继续，退休 store 不停顿。默认 qsort 从 159,843 变为 159,846 周期，其余五项不变，IPC 为 1.104759629；最终面积/频率见本页开头。
6. 独立尝试过分配回绕位、原始写回唤醒、store 额外寄存级、更多 MSHR、缩小乘法延迟、加大 PRF，以及不复用同拍释放的 IQ 槽。它们未合入最终实现。特别是保守 IQ 分派使 IQ8 的 IPC 降至约 1.0934，低于门槛，不能用这种方式换取频率。

最终保留真实可切换的 ISSUE_WIDTH=1/2、DECODE_WIDTH=1/2、ROB/PRF/IQ 容量和 ASSOC=1/2。ROB 并行恢复、store 同拍捕获、MSHR/响应队列的恢复身份过滤等已有修复继续保留。
